A compact Engine block added to the Composer's Video panel (above Generate) lets the user choose the provider (Demo — free, always works · Pollinations — their key, real, costs Pollen) and, for Pollinations, the model (seedance / veo / wan-fast) — without leaving the Composer. The per-request provider + model already exist on the backend schema, so this is front-end only. Three states:

Why these choices (ui-ux-pro-max)

  • progressive-disclosure The Model select only enables for Pollinations — Demo has no model, so showing one would be noise. Picking a provider reveals exactly the options it needs.
  • empty-state · nav When no key is saved, the Pollinations option stays visible but disabled with "add key in Settings" + an inline link — it explains *why* and the fix, instead of silently hiding the capability.
  • cost-clarity The cost line swaps with the provider: green "Free, instant" for Demo, amber "Uses your Pollinations credits (~1 clip)" for Pollinations — the spend is disclosed at the decision point, reinforced by text (not color alone).
  • sensible-default Defaults to Demo when no key (so Generate always works), otherwise the workspace's saved default provider/model — the picker is an override, not a required choice.
  • graceful-failure Choosing Pollinations with no Pollen still fails cleanly to a "no credit" message (existing backend behavior); the cost cue sets that expectation up front.
  • loading-buttons · a11y During generation both selects + Generate disable; every control has a real <label htmlFor>, ≥40px height, and a visible focus ring; the Generate label reflects the chosen engine ("Generate with Pollinations").
  • consistency Same select styling, grid, and spacing as the existing Aspect/Duration row and the Settings video block — one mental model across the app.
