Gemini + Higgsfield — Creative-Engine Plan

Implementation plan · 15 tasks · 5 phases · docs/superpowers/plans/2026-06-18-gemini-higgsfield-creative-engine.md

Goal: Collapse the AI stack to two vendors — Gemini (captions + images + embeddings) and Higgsfield's own API (platform.higgsfield.ai, cinematic video) — behind a swappable abstraction. Delete Claude, OpenAI, Pollinations, ElevenLabs, and the direct Runway/Kling/Veo providers.

Architecture: Keep the existing seams (VideoProvider interface, VideoGenerationService pipeline, BYOK resolver). Swap the implementations behind them. No vendor is a single point of failure — a second provider later is a new class, not a rewrite.

Stack: NestJSNext.jsPrisma + SupabaseZod@google/generative-aiHiggsfield RESTCloudflare R2Jest

Three judgment calls baked in

🧠 Embeddings → Gemini, not deleted. Cutting OpenAI would've silently broken the brand-memory moat's embedder. Migrated to gemini-embedding-001 @ 3072d to match the existing Pinecone index.

🎬 Video pipeline kept. The job/runner/reaper/R2/polling is provider-agnostic and solid — only the 5 provider implementations die. Less destructive = smoother.

🎙️ Faceless-videos rewired, not deleted. It needs voice (v1.1), so it's kept compiling on Gemini; recommended hidden from nav in the separate UX plan.

Two things the implementer must confirm live

🔌 Higgsfield model id + request fields — auth (Key key:secret) + async pattern (request_id → /requests/{id}/status) are confirmed from the docs; confirm the model id (higgsfield-ai/dop/standard) + body field names on the live model page. The real call is written — a one-page check, not blank work.

🔢 Gemini outputDimensionality — confirm the installed @google/generative-ai accepts it; the runtime call is written either way.

Standing risks (honored, not hidden)

⚠️ Higgsfield ToS for SaaS wrapping is unverified — fine to build, must be legally cleared before charging money.

⚠️ Mandarin quality is untested — every provider task includes a manual EN + 中文 smoke check.

⚠️ Higgsfield key (api_key:api_key_secret) is BYOK — user-supplied; never committed.
