Generate caption (Gemini) · image (Gemini) · video (Higgsfield, async, manual "Attach")

client-side attachedImageIds per platform → MediaAsset ids
▼   Save draft → 1 call  ·  Schedule → 2 calls

PostsService.create → Post (DRAFT or SCHEDULED) + PostVariant per platform + PostMedia
4 · POST /posts/:id/schedule
PostsService.schedule → just sets status=SCHEDULED, scheduledFor
▼
🔴 THE BREAK — nothing connects "SCHEDULED" (or any button) to "enqueue a publish job".
The producer SchedulerService.schedulePost() exists but no code calls it. There is no "Post now" route. Posts never leave SCHEDULED.
▼  (everything below is built but unreachable today)
5 · publish queue (BullMQ)
delayed job publish-post · needs Redis · producer orphaned
6 · PublishProcessor
refresh token → connector.publish() per variant → write PostPublication
▼
7 · Connectors
LinkedIn / Facebook / … publish() → {platformPostId, url}
8 · PostPublication
per-platform SUCCESS/FAILED · then Post → PUBLISHED / FAILED
9 · Analytics pull
on-demand only (no cron) · needs Redis · → PublicationMetrics

Post status lifecycle (as coded)

DRAFT ───(schedule)──▶ SCHEDULED ──✗ stuck forever (no enqueue) ✗──▶ [PUBLISHING ▶ PUBLISHED | FAILED] └─ only if a publish job ran, which never happens CANCELLED ◀── POST /:id/cancel (but doesn't dequeue any job) PENDING_APPROVAL / APPROVED ── set by approvals module, ignored by the publish path

Gaps the trace found

CRITScheduling disconnected

schedulePost() never called; POST /:id/schedule only sets DB status. Scheduled posts never publish.

CRITNo "Post now"

Composer has only Save draft + Schedule. No immediate-publish endpoint exists anywhere.

FRAGILEPartial failure → whole post FAILED

If 1 of 3 platforms fails, Post status = FAILED even though 2 succeeded. No "partially published" state.

FRAGILERetry re-publishes successes

BullMQ attempts:3 re-runs ALL variants; already-succeeded platforms could double-post.

FRAGILEBilingual bug

buildCreatePostInput hardcodes language:'en' — RedNote 中文 captions are stored as 'en'. Contradicts the bilingual edge.

FRAGILENo media-readiness guard

Nothing links a VideoGeneration job to a Post. Once scheduling works, a post could fire before its video is ready.

LOWCancel doesn't dequeue

cancel sets CANCELLED but wouldn't remove a Bull job (once scheduling is wired).

LOWIDOR on mutations

schedule/cancel/PATCH/GET :id skip workspace-membership checks.

LOWRedis-gated

Queue + scheduling only load when REDIS_URL is set. Local dev (no Redis) can't publish/schedule at all.

✅ TARGET design (after grill — 2026-06-18)

the fix: in-process cron, no Redis, DB-sourced, per-platform
1 · Composer → schedule
pick time → POST /posts + /schedule → Post SCHEDULED + scheduledFor · variant stores REAL language (en / zh-CN)
▼
2 · @Cron (~every 1 min)
scan posts where status=SCHEDULED AND scheduledFor<=now · same pattern as the video reaper · no Redis
3 · Atomic claim
flip SCHEDULED → PUBLISHING in one update so overlapping scans can't double-fire
▼   per variant (platform)
4 · Publish each platform
reuse existing logic: refresh token → connector.publish() · skip any platform already SUCCESS (idempotent — no double-post)
5 · Record per-platform
PostPublication SUCCESS / FAILED(+retryCount, nextRetryAt). Failed → auto-retry next cron passes, capped.
▼
6 · Roll up Post status
PUBLISHED (all ok) · PARTIALLY_PUBLISHED (new — some ok) · FAILED (all failed, retries exhausted)
7 · Cancel = just works
set CANCELLED; cron ignores it. No queue job to dequeue.
