UI design spec · Track A · Settings + Composer ui-ux-pro-max shadcn / Tailwind theme

Three surfaces let a workspace turn on real, prompt-driven video with their own Pollinations key while Demo stays the always-free fallback. The guiding constraints: keys are secrets, generation costs the user money (pollen credits), and every disabled control must say why and how to fix it. Each block below is annotated with the ui-ux-pro-max rule it satisfies.

Why these choices

  • forms · input-labels Visible “API key” label, never placeholder-only; aria-describedby ties the helper text to the input.
  • a11y · secret type=password + autocomplete=off so the key is masked and never autofilled/stored by the browser. Matches the 3 existing cards (consistency).
  • forms · disabled-states Save is disabled until ≥10 chars (≥0.5 opacity + title), so the primary action can’t fire empty.
  • color-not-only Status uses a ✓ glyph + text “Configured · ending 9f2c”, not green alone — readable for color-blind users and screen readers.
  • forms · cost-clarity The amber note sets the money expectation before the user commits — “costs pollen credits per video.” No surprise billing.
  • a11y · target Inputs/buttons ≥40px tall; the “Get a key + add credit” link opens pollinations.ai in a new tab with an external-link glyph.

Why these choices

  • nav · empty-state The disabled option reads “Pollinations — add key first” rather than vanishing — it explains why it’s unavailable and points to the fix, instead of silently hiding.
  • forms · progressive-disclosure The model picker stays disabled until a real (non-Demo) provider is chosen, so users aren’t shown irrelevant choices.
  • forms · input-helper-text Model labels carry the supported duration range (2–10s etc.) so the choice is informed without docs.
  • forms · cost-clarity The footer states Demo-vs-Pollinations and the per-clip credit cost in the same breath, reusing the amber money cue.
  • consistency Identical control styling, focus ring and grid as the Caption/Image blocks directly above it — one mental model.

Why these choices

  • perf · progressive-loading A >1s wait gets an indeterminate progress bar + elapsed timer + “~30s” estimate — not a bare spinner — so the wait feels bounded.
  • forms · cost-clarity “Uses your Pollinations credits” sits next to Generate in the idle state — the spend is disclosed at the moment of decision.
  • forms · error-recovery + error-clarity Failure states the cause (“out of pollen credits”) and the fix (top-up link) and offers “Try again.” The reaper’s timeout maps to the same pattern.
  • a11y · aria-live Status region is aria-live="polite"; the error is role="alert" — state changes are announced to screen readers, toasts don’t steal focus.
  • animation · reduced-motion Spinner and progress shimmer collapse to a static fill under prefers-reduced-motion (toggle your OS setting to verify).
  • style · success-feedback The done state is visually distinct (playable poster + green confirmation) and leads straight to the next action — Attach to post.
