The connector itself is backend (OAuth + resumable upload). It surfaces in just two places in the UI: (1) connecting the YouTube account in Settings, and (2) a per-post privacy control in the Composer. Everything else (the enum, platform specs, the generic OAuth route, the platformOptions field) already exists.

Design notes

  • per-post privacy The segmented Public/Unlisted/Private control writes to the existing platformOptions.youtube.privacyStatus — no schema migration. Defaults to Unlisted if untouched (safe).
  • a11y · radiogroup Privacy is a segmented role="radiogroup" (arrow-key nav, aria-checked, ≥44px targets) — all three options visible, one tap; the selected state reads by fill + text, not colour alone.
  • destructive · confirm Disconnect asks to confirm (restoring needs re-OAuth). On an image-only post the privacy control stays active — only the YouTube publish is blocked, shown as a role="alert" — so the two concerns aren't conflated.
  • video-only YouTube's spec already says supportsImage:false; the Composer warns on an image-only post and the connector throws a clear error rather than uploading junk. The draft still saves.
  • title Uses the post's title field, falling back to the first line of the caption (≤100 chars) — YouTube requires a non-empty title.
  • refresh tokens Google access tokens last ~1h, so the connector implements refreshToken() and the worker refreshes before uploading — the user connects once.
  • quota videos.insert costs ~1600 of ~10k units/day (~6 uploads). A 403 quota error surfaces as a clear, retryable message rather than a generic failure.
  • reuse The connect button + generic OAuth route + SocialAccount storage already exist — this adds one registry entry, one OAuth param-map line, and one list item, plus the connector + the privacy control.
