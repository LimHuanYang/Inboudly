Runtime architecture

Request flow top-to-bottom. The browser talks only to the NestJS API over REST (/api/v1); the API owns all data, infra, and outbound AI calls. Each customer brings their own AI keys (BYOK), so AI usage never touches the platform's bill.

Spotlight: async video generation flow

The newest feature. Because real providers take 30s–minutes, generation is a job: the request returns immediately and the client polls. A built-in keyless Demo provider is the always-works default; paid providers are pluggable behind a single VideoProvider interface.

Submit Composer → POST /api/v1/ai/video

User picks Video, enters a prompt. Body validated by ZodValidationPipe(GenerateVideoSchema); SupabaseAuthGuard + assertMember enforce workspace access.

Resolve & create job VideoGenerationService · AiCredentialsService

resolveVideoProvider honours the workspace's preferred provider (or falls back to Demo). A VideoGeneration row is created as GENERATING and returned instantly.

Run detached VideoProvider.generate()

A fire-and-forget runner calls the provider adapter (DemoVideoProvider today). On success it registers a MediaAsset via MediaService and flips the job to READY + mediaAssetId; on error → FAILED with a friendly message.

Poll GET /api/v1/ai/video/:id

The Composer, the Generations tray, and the Media library poll (TanStack Query refetchInterval) only while jobs are in flight — stopping once terminal.

Consume Composer · Tray · Media library

READY clip plays inline, attaches to the post (same path as images), and surfaces as a Media tile. In-flight jobs render shimmer placeholders.

Cross-cutting concerns

Patterns applied consistently across modules.

Auth & multi-tenancy

Supabase JWT via SupabaseAuthGuard; Tenant → Workspace → Member, gated by assertMember on workspace-scoped routes.

BYOK key security

Per-workspace AI keys stored AES-256-GCM encrypted in WorkspaceAiCredentials; resolved per request, never logged or returned.

Validation

Zod everywhere — shared schemas drive a ZodValidationPipe + global ZodExceptionFilter so bad input is a clean 400, not a 500.

Provider + model per task

Caption, image, and video each resolve a provider+model independently, with a guaranteed free fallback (Pollinations for image, Demo for video).

Async jobs

Long work (publishing, video) is modelled as status-tracked jobs (VideoStatus enum) with client polling; BullMQ backs scheduled publishing.

Type-safe contracts

Request/response shapes live in @inboudly/shared (zod) and DB types in @inboudly/database (Prisma) — one source of truth for both apps.
